## 1. Executive summary

The codebase remains mature in the style sense 132 commits after the previous style analysis. ktlint is green. The codebase has no `!!`, no TODO, no wildcard import, no mocking library, and no `assertThatThrownBy`. All 484 tests carry the CONTRIBUTING rationale block and a `should …` backtick name, and English is used throughout. The degree of "Java in Kotlin" remains near zero:

- `require`/`check`, `when` expressions, `object` constants, enums with `tagValue`, and `fun interface` seams with typed `@JvmField` defaults.
- `internal` as the default visibility (40 of 51 top-level declarations in common/RestClient).
- Constructor-only wiring and one validated `@ConfigurationProperties`.

The previous report's patterns are closed. Throwing fakes use `error(…)` everywhere except two new sites, logger naming is uniformly `internalLog`, and the emitter member order is identical in both twins.

The new findings cluster around the ADR-0015 change (blocking `cancelled`), which updated the code faster than the prose. The **High** item is that four KDoc passages in the WebClient twin still describe `cancelled` as "the reactive reality a blocking call cannot have". One of them is the list that calls itself "canonical" and contradicts the README table it claims to mirror. Four test rationales, which are published on the test-evidence page, say the same (Medium).

The second cluster is the **test tree outside the tool net**. ktlint 1.8 no longer flags unused imports, and the CI comment lint greps only `src/main`. As a result, 20 unused imports have accumulated in 8 test files, and a `[Symbol]` link sits in a `//` rationale. Production has neither.

The rest is within-module duplication in the new interrupt and pool scenarios, a few test-seam markers that no longer match their member, stage-comment placements, and polish. The CauseGraph change of the defect-fix round of 2026-10-23 leaves two small inconsistencies (findings 17 and 34).

## 2. Baseline & methodology

**Enforced rules (authority 1).**

- **ktlint `ktlint_official`**, bound to `verify` and green. It covers main and test sources (probe). Formatting, wrapping, trailing commas, import **order**, and indentation belong to the tool and are not reported by hand.
- **Unused imports are no longer tool-owned:** ktlint rule set 1.8.0 does not report them (probe), so they are judged here (P2).
- **`./.editorconfig`:** UTF-8, LF, 4-space indent, `max_line_length = off` (a decision; line length is never a Kotlin finding).
- **CI comment lint (`./.github/workflows/ci.yml:57-86`):** no `[Symbol]` in `//` comments, no section numbers, no report citations. It covers **`legatium-*/src/main` only**.
- **Dokka `failOnWarning`** checks KDoc links in the twins.

**Documented conventions (authority 2).**

- **`./CONTRIBUTING.md` "Code style":** comments state constraints, not narration.
- **`./CONTRIBUTING.md` "Tests":**
    - Rationale block (`What is tested:` / `Success criteria:` / `Why it matters:`), then Given/When/Then stage comments.
    - A `[Symbol]` in a `//` comment "only LOOKS checked … name the symbol in backticks there".
    - Engine suites pin the module's classification, not engine exceptions.
- **ADR-0003:** twin copies above the contract line are deliberate. The test-helper copy exception was revoked by commit `29ebfac` ("Share the twins' test helpers through legatium-common's test-jar"); only engine fakes, Spring fixtures, and peer extensions stay per twin.
- **ADR-0007:** `Client*` code names beside the `adapter_*` vocabulary.
- **ADR-0013:** comment prefixes (`Invariant:`, `Assumption:`, `Workaround:`, `Safety:`, `Rationale:`); new comments of a category carry the prefix as they are written.
- **ADR-0015:** both stacks share the whole outcome vocabulary, `cancelled` included.

**De-facto house style (authority 3), rechecked at this commit** (basis: grep over `src/main/**/*.kt` unless stated):

- **Visibility:** `internal` by default. Members exposed for tests carry `internal` plus a KDoc "exposed for the tests": 6 of 9 in common/RestClient and 3 of 4 in the WebClient twin (findings 3, 4, 11, 20).
- **`var`:** 19 in common/RestClient and 11 in the WebClient twin, all `@Volatile` lifecycle state, lock- or thread-confined capture state, locals, or the `ambientRestorer` seam (kept by decision). No `lateinit` except the two subscribers' `upstream`.
- **Constants:** SCREAMING_SNAKE for all 18 deeply immutable `val`s and 38 `const val`s. Companions put constants before functions everywhere except one (finding 19).
- **Bodies:** about 56 expression and 68 block bodies, with no block body that only `return`s an expression.
- **Tests:**
    - Throwing fakes use `error(…)`: common 8/0, RestClient 6/0, WebClient 8/2 (finding 22).
    - Recorded nullable values are read with `requireNotNull`: 22 against 2 `checkNotNull` (finding 27).
    - Recording fakes declare `private set` (6 of 6 outside `CapturingDecoratorsTest`).
    - Counter reads go through the shared `MeterRegistry.count` (`./legatium-common/src/test/kotlin/eu/inqudium/legatium/common/MeterAssertions.kt:6`).
    - Bounded cross-thread actions go through `onAnotherThread`.
    - Stage labels: the bare and the `Label: text` form are both accepted by `./.github/scripts/generate-test-catalog.py`. Every label in scope is in its vocabulary.
- **Java projects:** hand-formatted in google-java-format shape at 100 columns (P8 of the previous report).

**Prior findings.** The previous report's resolutions were spot-checked and hold: the `MeterRegistry.count` extension, `error(…)` in fakes, the emitter member order, `internalLog`, the typed `CallerMdcSnapshot.NONE`, and `IntegrationApp` in its own file. Its finding 4 was left partial "because the module has no TestSupport.kt". That premise is gone now that `MeterAssertions.kt` lives in `legatium-common` (finding 7).

**Blind spots.** No executable style tool for Java, no detekt-class metrics. Judgments on duplication (findings 14, 33) carry medium confidence because extracting the shared code could cost more than it saves.

## 6. Systemic patterns

**P1 — Prose behind ADR-0015 (production + tests, High via finding 1).** 8 sites still describe `cancelled` as reactive-only: 4 in WebClient production KDoc and 4 in WebClient test rationales or names (findings 1, 2). A 9th site, `ObservedBody.kt:33`, was fixed in the defect round of 2026-10-23. Counting basis: the four review passes, confirmed by `grep -E 'cannot have|does not have|cannot be\)|on top of the RestClient|reactive (outcome|disposition)|like .cancelled.'` over `legatium-*/src`. The RestClient twin and common are clean. Strategy: one sweep along ADR-0015's wording, "what `cancelled` means on each stack".

**P2 — The test tree lies outside the tool net (tests, Medium via findings 5, 6).**

- ktlint rule set 1.8.0 has no unused-imports rule; the worktree probe confirmed this. **20 unused imports in 8 test files** were counted by a script (an import whose simple name or alias does not occur elsewhere in the file) over all `*.kt`/`*.java`. Production and Java: 0.
- The CI comment lint greps only `legatium-*/src/main`, so the test tree's `[Symbol]` rule is checked by nobody (1 site).
- Strategy: remove the imports; extend the comment-lint greps to `src/test` (the rule is documented for tests); for unused imports, enable a compiler/IDE-independent check (for example the Kotlin compiler's warnings as errors for the test compile, or a grep step like the existing ones), or accept a manual sweep per release.

**P3 — Within-module duplication in the new test scenarios (tests, Medium via findings 7-9).** Interrupt scaffolding ×4, poll loop ×3, exhausted-pool setup ×2, counter-read spellings ×3 in `ClientLoggingMetricsTest`, gauge read ×7 (finding 23), failing MDC adapter ×2 (finding 33), cycle test ×3 (finding 34). **P4 — Stage-comment placement (tests, Low).** Act under `Then` (4 sites, finding 10), act under `Given` (1, finding 30), assertions under `When` (5, finding 31), `When/Then` followed by `Then` (4 sequences, finding 29): 14 sites among 484 tests. Every label is in the generator vocabulary.

**P5 — Test-seam marker out of step with the member (production, Medium/Low via findings 3, 4, 11, 20).** 5 members: one marker on a `private` member describing a seam that does not exist (3), one `internal` member without a test use (4), one marker that omits the production user (11), and three test-only `internal` members without a marker (20, counted as one finding). **P6 — Captured `var` recorders and open setters (tests, Low, residue of the previous P6).** 3 local `var` recorders (finding 24) and 3 public recorder setters (finding 25). The previous round removed most of them; these are new or were outside its list.

- **14** (subscriber scaffolding): no shared base subscriber.
