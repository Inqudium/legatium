## 1. Executive summary

The comment base of legatium carries knowledge. With 43 % comment lines it is dense, but it is mechanically clean:

- 0 TODO/FIXME, 0 lines of commented-out code (both heuristic hits in production are prose), 0 ceremonial `@param`/`@return` blocks
- 441 KDoc links, all checked by Dokka, and 0 links in `//` comments
- 485 of 485 tests carry the complete rationale block

The largest reaches of comment text (the operator classes `ObservedBody`/`ObservedResponse`, the meter owner, the bounded byte buffer, the response tee) are why and why-not knowledge with named failure modes, in the right place. No hygiene pass may touch them.

The debt does not lie in volume. It lies in **contract statements that can turn wrong unnoticed, and have done so in places**:

- Three statements in public KDoc contradict the code (findings 1-3):
  - The WebClient filter's fail-open promise "a tee that throws costs one buffer's capture … Calls are never affected" does not hold for the request side. There the tee runs unguarded in `map`, which is also a code defect.
  - `logResponseBody` promises "nothing is captured in vain", although `ON_FAILURE` buffers every response.
  - `BodyReadState` asserts that the request count is "what went out", which guide §7.8 refutes.
- Seven further High findings concern public contracts that are underspecified or claimed too broadly (meter tags, header masking, the id contract, "every bean backs off"), and three test guards that are claimed but pin less than they say.

The systemic center of gravity is **ADR-0013 applied in name only**. About 98 sentences in production state an assumption, a guard purpose, an invariant, a rejected alternative or a compatibility constraint, but only 27 carry a prefix (15 of them `ELK:`). That includes `Cancellations.kt`, which was written after the ADR, and the files touched on 2026-10-23. The dependency-upgrade grep that ADR-0013 promises therefore finds less than a third of the stock.

**Conclusion.**

1. **State:** more knowledge than dead weight. True dead weight (ceremony, chronicles without consequences, filler) amounts to a few dozen lines. The center of gravity of the debt is drift in contract prose, especially public property and API KDoc that no test pins, plus the unprefixed category stock. About 30 statements can silently become wrong in a way that matters. These are the findings in sections 5.1-5.3: 14 actual contradictions or over-claims, plus the unpinned third-party facts.
2. **Reducibility and limiting factor:** condensation yields about **40-60 production comment lines (≈ 2 %)**. These are mainly repetitions of the same rule along a chain (count before copy ×4, handover read ×4, exactly-once CAS ×3, the `ofStatus` matrix ×2, own keys ×3) and a few chronicles. Two things limit it. First, half of the High findings ADD text (public KDoc is sharpened). Second, the prefixing changes the stock without shortening it. There is **one decomposition** (`ClientRequestLoggingInterceptor.intercept`, finding 16); because a new KDoc frame has to be created, its line balance is about zero. Missing names or types are not a limiting factor; the identifiers are good.
3. **Most essential risks & anomalies:**
   - 🔴 The fail-open promise of the WebClient filter for a throwing tee is false on the request side, and the code shares the defect (`./legatium-webclient-logging/src/main/kotlin/eu/inqudium/legatium/webclient/logging/CapturingDecorators.kt:69-70`; finding 1).
   - 🔴 Public body KDoc in `ClientLoggingProperties`/`BodyLogMode`/`BodyReadState` misrepresents the capture and measurement semantics (findings 2, 3).
   - 🟠 Test guards that are named as such are weaker than their rationale and the production KDoc that points to them: the counter width, the Reactor Netty pool acquire, the type half of the field "lockstep" (findings 8, 9, 14).
   - 📚🔴 places that a careless reduction would destroy, all at score-4/5 files: `ObservedBody.kt:63-76` (first subscription only, error picture on 3 of 4 connectors), `ClientLoggingMetrics.kt:134-140` (lock order), `BoundedByteBuffer.kt:17-25, 231-233, 243-249`, `AmbientContextRestorer.kt:45-50` (two-loader check), `CapturingClientHttpResponse.kt:14-33` (emission at close, completion rule), `ClientRequestLoggingInterceptor.kt:276-288, 335-342`. The full list is in section 7.
   - Systemic: unprefixed category comments (P1, ≈ 98), spoke repetitions of a canonical rule (P3), textual references to guide headings and KDoc sections (P4), engine facts in test KDocs outside the upgrade grep (P5).

## 2. Scope & methodology

**Analyzed:** all 43 production files completely, in three module-wise reading passes; the test inventory mechanically. Read in depth: the fixtures (`TestSupport.kt` of both twins, `PeerServer`, `Tarpit`, `CapturedLogger`, `MeterAssertions`, `MdcAdapterSwap`), both engine contracts and all engine suites' class KDocs, both `TwinContractTest`s, `CancellationsTest`, `CauseGraphTest`, `TimeoutsTest`, `ClientRequestLoggingInterceptorCancellationTest` and `CountingCorrelationIdGeneratorTest`, plus the test behind every production pin claim. **Not analyzed:** Markdown as a subject, workflows, POM comments, benchmarks.

**Test code:** in scope. The tests are the only example carrier; there is no `@sample`. Of 27 pin claims in production KDoc, 25 are correct and 2 are partly false (findings 9, 14). In addition, two test rationales claim more than their test pins (findings 8, 15). All 8 members marked "exposed for the tests" are used by tests, and all 13 backticked `should …` cross-references resolve.

**Boundary between public API and internal:** the 12 public types listed in the metadata block, plus their public nested configurations and `@Bean` methods. Their KDoc is to be sharpened, not shortened. Four of the five most serious findings concern public KDoc, and they add text.

**Convention sources:** CONTRIBUTING and ADR-0001 to ADR-0015 (see the metadata block). ADR-0013 is the yardstick for prefixes. Its grammar: the prefix opens the sentence that makes the statement, one prefix per statement, most comments carry none, and new comments of a category carry the prefix as they are written.

**Existing prefix vocabulary in production:**

| `Invariant:` | 6 |

**Documentation run:** checks references (`failOnWarning=true`), so `[Symbol]` links can be relied on. Unchecked, and therefore drift-prone: prose references to guide headings (`docs/GUIDE.md` section titles), to KDoc sections ("section 'Manual wiring' of the class KDoc") and to tests by description ("the tracing integration test").

**Churn period and counting basis:** the entire history (2026-09-03 to 2026-10-23, 305 commits) and the last 30 days, by file via `git log --format= --name-only`. The highest churn, 23-25 commits, is in the two entry points and the two emitters; the 30-day churn is low (at most 4, in `Timeouts.kt`).

**Blind spots:** whether a sentence is "obvious" was judged against a reader without the context of the neighboring classes. The prefix counts per category come from reading, not from a grep, and are therefore approximate (±10 %). The Markdown guides themselves were not audited; deviations found there are noted as side remarks.

## 5. Findings

Numbered consecutively; grouped by criticality. Paths relative to the workdir.

### 🔴 Critical

- [x] 1. [`./legatium-webclient-logging/src/main/kotlin/eu/inqudium/legatium/webclient/logging/ClientRequestLoggingFilter.kt:103-106`, `./legatium-webclient-logging/src/main/kotlin/eu/inqudium/legatium/webclient/logging/CapturingDecorators.kt:20-22`; code `./legatium-webclient-logging/src/main/kotlin/eu/inqudium/legatium/webclient/logging/CapturingDecorators.kt:69-70`, `:76-78`] {Critical} {Confidence: high} {📚⚪} {Drift & staleness / API documentation}
  - The public fail-open promise for a throwing tee is false on the request side.
    - Finding: the filter KDoc (public) says "Identical contract to the RestClient twin: … a tee that throws costs one buffer's capture (`stage=wiring`) … Calls are never affected"; the tee KDoc says "the copy can [throw] … and [ObservedBody] lets it". Only the response tee is guarded (`ObservedBody.onNext`). On the request side `tee` runs unguarded in `body.map { tee(capture, it) }`: a throwing `toByteBuffer` turns into the error signal of the connector's body write, and the call fails. "Identical contract" is false too, because the RestClient twin copies the request body inside the fail-open wiring. **Overlap with a code defect**; it belongs to the defect analysis.
    - Information class: Contract
    - Drift test: yes; no test exercises a throwing request tee
    - Actionability: yes; a host trusts "Calls are never affected"
    - Carrier strategy: first the code (guard the request tee like the response tee), then a test analogous to the response side's `should deliver the buffer untouched and count stage wiring when the tee itself throws`. Until then, the KDoc must restrict the promise to the response body.
    - Residual information: "counted before the copy: a throwing copy costs the text, never the size"
    - Target location: `ClientRequestLoggingFilterBodyAndHeaderTest` (new test); the filter KDoc section "Fail-open"
    - Pass: 4 (code + test), immediately

- [x] 2. [`./legatium-common/src/main/kotlin/eu/inqudium/legatium/common/ClientLoggingProperties.kt:88`; `./legatium-common/src/main/kotlin/eu/inqudium/legatium/common/BodyLogMode.kt:8-11`] {Critical} {Confidence: high} {📚⚪} {Drift & staleness / API documentation}

    - Information class: Contract

- With `COUNTER_WIDTH` 7, the reworked width test fails (alongside the format tests).

Decisions:
- **7** (host id): the KDoc states the rule (1-200 visible ASCII characters, ADR-0002) and the consequence of breaking it. The optional `check` is declined: a throwing check would turn a host bug into a dropped log line.
- **22** (guide-heading references): kept as unchecked prose with their residual statements, by decision; the two KDoc-section references now name the class with a checked `[link]`.
- **48** (`GENERATED_ID_ATTRIBUTE`): stays public (removing it would be an API change). Its KDoc says the interceptor sets it and a host must neither set nor read it.

Consequences worth knowing:
- **1** is a code fix. `teeOrPass` in `CapturingDecorators.kt` is the one fail-open guard of both tee directions. The decorators and `withRequestBodyTee` take the failure reporter as a required parameter, so no silent default exists. The new test is `ClientRequestLoggingFilterBodyAndHeaderTest` "Request body tee"; CHANGELOG `[Unreleased]`, Fixed.
- **8**: `should keep the fixed width up to the last counter value the width can hold` now asserts counter 0 and 36^8-1 as exact strings on a non-zero prefix, so a narrowed counter fails too.
- **9**: new `ReactorNettyConnectorIntegrationTest` test `should log this connector's pool acquire timeout as WARN timeout`. It pins the classification, and the exception type is an `Assumption:`, per the CONTRIBUTING engine rule.
- **14**: `ClientLogField.type` is `internal`; `ClientLogFieldTest` derives the expected index type of every field from it.
- **15**: both Apache 5 lease tests run on a platform and a virtual thread (`@EnumSource`).
- **16**: `ClientRequestLoggingInterceptor.intercept` has its own KDoc with the disposition contract.
- **18**: the teardown rule lives on `WiringCost.DIRTY_TEARDOWN`; its three spokes link there.
- **25**, P5: engine facts in the engine suites' KDocs are `Assumption: … (probed on …)` lines. ADR-0013 and CONTRIBUTING now give the upgrade grep as `grep -rn "Assumption:" */src` (main and test), with a History entry in ADR-0013.
